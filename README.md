# Инвертированный индекс и словарь — веб-версия

Веб-версия лабораторной работы №1 «Построение инвертированного индекса и словаря»
по курсу «Распределённые системы обработки информации» (вариант 8).
Исходное приложение было написано на Kotlin + Jetpack Compose под Android;
эта версия — статическая веб-страница на **Vite+**, **Svelte** и **shadcn-svelte**.

Вся обработка (чтение файлов, токенизация, стемминг, построение индекса, поиск)
выполняется полностью в браузере — бэкенд не нужен.

## Стек

| Инструмент | Назначение |
| --- | --- |
| [Vite+ 1.5](https://viteplus.dev) (`vp`) | единый тулчейн: создание проекта, dev-сервер, сборка, форматирование, линт |
| SvelteKit 3 + `adapter-static` | маршрутизация и полностью статическая сборка (SPA с fallback-страницей) |
| Svelte 5 (runes) | реактивность (`$state`, `$derived`, `$effect`) |
| TypeScript | типы (порт моделей данных из Kotlin) |
| Tailwind CSS 4 | стилизация |
| shadcn-svelte (пресет **nova**) | UI-компоненты: кнопки, карточки, таблицы, сворачиваемые панели и т.д. |
| `@lucide/svelte`, `mode-watcher`, `svelte-sonner` | иконки, светлая/тёмная тема, всплывающие уведомления |

## Что делает приложение

Пошагово повторяет работу программы из отчёта:

1. **Выбор документов** — кнопка «Выбрать файлы» или перетащите `.txt`-файлы в пунктирную зону;
   для быстрой демонстрации есть кнопка «Демо-тексты» (генерирует 100 тематически схожих
   документов по 1000+ слов — как требует задание).
2. **Чтение текста** — содержимое каждого файла считывается, сохраняются имя и путь
   (в браузере полный путь недоступен, поэтому хранится имя файла).
3. **Токенизация** — нижний регистр, тире заменяются пробелами, всё небуквенное удаляется
   регуляркой `[^\p{L}\s]`, пробелы схлопываются, текст разбивается на слова.
4. **Алгоритмический стемминг** — перебор русских суффиксов и обрезка подходящего,
   если после обрезки остаётся больше двух символов (точный порт `stem()` из оригинала).
5. **Удаление стоп-слов** — тот же список из 117 служебных слов, что и в оригинале.
6. **Построение инвертированного индекса** — `Map<стем, TermInfo>` (аналог `HashMap`):
   для каждого термина хранятся постинги `{docId, termFrequency, positions}`.
   Гибридная схема оригинала сохранена: O(1)-доступ по хешу + растущие списки постингов.
7. **Поиск** — «Показать формы слова» находит все исходные формы слова во всех документах
   и помечает документы, где слово встречается; «Поиск в документе» открывает текст
   документа с подсветкой всех вхождений (текущее — синим фоном), навигация кнопками
   «Пред./След.» или стрелками ← →, автопрокрутка к текущему вхождению.

На экране «Инвертированный индекс» — словарь терминов, отсортированный по частоте
в коллекции (как в оригинале показывались первые 50), с раскрытием постингов,
фильтром по подстроке и подгрузкой порциями по 50.

## Запуск

```bash
npm install        # то же самое: npx vp install
npm run dev        # дев-сервер с HMR → http://localhost:5173
npm run build      # статическая сборка в каталог build/
npm run preview    # локальный просмотр собранного сайта
npm run check      # svelte-check: проверка типов
npx tsx tests/smoke-test.mts   # smoke-тест логики (стемминг, индекс, демо-коллекция)
```

> **Замечание о глобальном `vp`.** Если Vite+ установлен глобально
> (`curl -fsSL https://vite.plus | bash`), запускайте команды через npm-скрипты или
> `npx vp …` из каталога проекта: глобальный бинарь при `vp dev` подхватывает вторую
> копию Vite, и SvelteKit падает с `vite_ssr_environment_not_runnable`.
> `npm run dev` всегда использует локальную версию из `node_modules` и работает корректно.

## Готовая статика

Каталог `build/` уже содержит собранный сайт. Его можно развернуть на любом
статическом хостинге (GitHub Pages, Netlify, nginx) или посмотреть локально:

```bash
npx serve build
# или
python3 -m http.server -d build 8000
```

Открывать нужно через `http://`, не двойным щелчком по `index.html` (браузер
не даёт загружать ES-модули с `file://`). Все маршруты (`/document/1`,
`/search/1/слово` и т.п.) обслуживаются единственной страницей `index.html`
(SPA-fallback) — заходить с корня или использовать сервер с fallback-логикой
(`vp preview`, `npx serve` умеют это из коробки).
