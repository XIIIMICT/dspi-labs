## Manual formula extraction note

The Lab 4 formulas (R, P, Fallout, F-measure) and the shingle example formulas are
embedded Equation Editor OLE objects rendered as WMF/PNG previews, so they do not
appear in plain-text extraction. They were decoded from the embedded preview images
(OCR of `word/media/image2.png` … `image11.png`) and cross-checked against the
surrounding prose definitions ("Тогда коэффициент полноты R и коэффициент точности
P…", "отношение числа найденных нерелевантных документов к общему числу
нерелевантных документов в базе", "взвешенное гармоническое среднее точности P и
полноты R"). The registry wording "величины -меры" is the plain-text remnant of
"величины F₁-меры" — the subscript was an embedded image, confirmed by the identical
OLE placeholder in the registry task text and the manual's assignment line
"коэффициенты точности, полноты, выпадения и F₁-меры".

## Cross-lab ambiguity resolutions

1. **Lab 3 language vs Lab 1 corpus (English vs Russian).** The manual's variant
   table row for 2/8/14 explicitly says `Английский` for Lab 3, and the assignment
   allows "любые тексты из лаб. раб. №1" (any texts from Lab 1) — Lab 1's table has
   both Russian and English rows, so a student with variant 2/8/14 uses English
   Lab 1 texts. Resolution: the Lab 3 input flow supports both selecting documents
   from the Lab 1 session corpus (accepting those meeting the ≥1000-word rule; a
   Russian demo document triggers a clear validation notice that the variant
   requires English) and importing files directly. No silent language conversion is
   performed.
2. **Lab 4 retrieval scenario.** Resolved as the shingle-similarity search described
   above: query text vs collection, threshold-based retrieval decision, ground truth
   by construction. This is the narrowest reading that keeps "согласно реализации
   своего алгоритма в лабораторной работе №3" true without inventing a separate
   Boolean/keyword search engine.
3. **Chart metric label.** `величины -меры` = F₁-меры (missing subscript was an
   embedded image; the preceding sentence names F1 explicitly). The chart plots F1.

## Shared architecture requirements

- Variant selection moves from `main-header.svelte` local state into
  `shell.svelte.ts` (keyed per lab, validated on lab switch, falling back to the
  first variant of the new lab).
- A registry-driven dispatch: `src/routes/+page.svelte` renders the active lab's view
  through a static folder→view map; a lab counts as implemented only when its view
  is registered (not merely because a store module exists).
- Lab 1 corpus exposed through a narrow read-only accessor for Lab 3 (document id,
  name, text) — no UI internals imported.
- Pure algorithm modules (no Svelte imports) so tests run under Bun directly.
