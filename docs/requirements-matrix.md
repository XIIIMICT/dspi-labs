# Requirements Matrix for Labs 1–4

Sources: `docs/Методичка.docx` (authoritative for algorithms), `src/lib/labs/registry.json`
(authoritative for titles, ordering, variant metadata). Lab ordinals are 1-based array
positions in the registry. All manual references below use the lab heading and section
names from the docx (page numbers are unavailable in the source file).

This document distinguishes three kinds of statements:

- **Manual** — an explicit requirement from the docx (or a literal formula from its
  confusion table / assignment).
- **Implementation choice** — a deterministic rule this app adopted where the manual
  is silent or incomplete. It is NOT attributed to the manual.
- **Source conflict / ambiguity** — an internal inconsistency or undefined detail
  in the docx that cannot be resolved by code alone.

## Manual formula extraction note

The Lab 4 formulas (R, P, Fallout, F-measure) and the shingle example formulas are
embedded Equation Editor OLE objects rendered as WMF/PNG previews, so they do not
appear in plain-text extraction. They were decoded from the embedded preview images
(OCR of `word/media/image2.png` … `image11.png`) and cross-checked against the
surrounding prose definitions ("Тогда коэффициент полноты R и коэффициент точности
P…", "отношение числа найденных нерелевантных документов к общему числу
нерелевантных документов в базе", "взвешенное гармоническое среднее точности P и
полноты R"). The registry wording now reads "F1-меры"; the original docx had the
subscript as an embedded image, so plain extraction showed "величины -меры".

| Manual reference                                             | "Лабораторная работа 3" → «Методические указания»: stages (канонизация → шинглы → 84 хэша → выборка 84 контрольных сумм → сравнение); канонизация also requires «приведение имен существительных в именительный падеж, единственное число, а иногда – оставление только их корневых значений». | Input contract                                               | Exactly 4 `.txt` texts, each ≥1000 words, from files OR from the Lab 1 session corpus (both are stated in the assignment: «любые тексты из лаб. раб. №1» AND «импортироваться из файлов»). Duplicates rejected by normalized content, not filename. Single-flight guard over async reads; every candidate mutation invalidates results.                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Processing pipeline                                          | 1) canonicalization: lowercase, strip punctuation/digits/HTML-like tags, remove English stop words, conservative offline singularization of KNOWN plural nouns; 2) overlapping shingles of 8 canonical tokens (count = tokens − 8 + 1); 3) 84 hash functions → minimum control sum per row; 4) similarity % = matched 84 sums / 84 × 100.                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Canonicalization (implementation choice / limitation)        | The manual states the noun-normalization requirement in RUSSIAN morphological terms. For English this app uses a conservative offline approximation: a `Map` of irregular plurals plus guarded regular candidates that are accepted only when confirmed against a local list of known singulars. This is NOT full морфологическая лемматизация с определением части речи (POS-aware lemmatization); root reduction («иногда») is deliberately not applied. Common singular/non-noun words (`news`, `series`, `species`, `physics`, `always`, `various`, `alias`) are preserved, and inherited object properties (`constructor`, `toString`) can never leak into canonical tokens. Source text is never mutated.                                                                 |
| Language-token counting (implementation choice / limitation) | `countEnglishWords()` counts `[a-z]+` Latin-letter TOKENS, not English words: French/Spanish/German/invented Latin-script text also passes the ≥1000 check. It is NOT a language detector and a passing count is NOT proof the text is English. The UI states that supplying text in the variant's language remains the user's responsibility. Lab 1's `\p{L}+` count is likewise a token count, not a Russian-language detector.                                                                                                                                                                                                                                                                                                                                               |
| 84 hash functions (implementation choice)                    | The manual requires 84 static hash functions and the per-row minimum, but does NOT define their byte-level construction. This app uses SHA-1 (the registered primitive) over `${salt}:${shingleText}` with salt `0..83`, folded to a 48-bit integer from the first 6 digest bytes (big-endian) — documented, with known-answer vectors. Not an exact formula from the manual.                                                                                                                                                                                                                                                                                                                                                                                                   |
| Empty sketches (implementation choice)                       | A text with zero shingles (stop-word-only, or < 8 canonical tokens) yields `valid: false` with NO sentinel sums; `compareSketches` throws `EmptySketchError`. Two empty texts can never be reported as 100% similar.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Language conflict (SOURCE CONFLICT — unresolved)             | Lab 1's variant table assigns 2/8/14 to «Гибридная схема / Русский»; Lab 3's variant table assigns the SAME variant numbers to `SHA1 / 8 / Английский`. Both paths stay supported, no silent translation, registry language fields unchanged. The conflict remains UNRESOLVED until the instructor supplies a consistent interpretation. |

## Cross-lab ambiguity resolutions (summary)

1. **Lab 3 language vs Lab 1 corpus (English vs Russian).** UNRESOLVED SOURCE
   CONFLICT: the same variant numbers 2/8/14 are Russian in Lab 1 and English in
   Lab 3, while the Lab 3 assignment allows texts "из лаб. раб. №1". English rows
   in the Lab 1 table belong to OTHER variant groups, not 2/8/14. No automatic
   translation, no silent registry change; direct English file import (also required
   by the Lab 3 assignment) is the practical path and the conflict is surfaced in
   the UI. The earlier statement in this matrix that Lab 1's table had English
   rows "applicable to variants 2/8/14" was a factual error and is corrected here.
2. **Lab 4 retrieval scenario.** Implementation choice, not a manual rule:
   query vs collection, threshold-based shingle retrieval, explicit user-supplied
   relevance labels. Keeps «согласно реализации своего алгоритма в лабораторной
   работе №3» true without inventing a separate Boolean/keyword search engine.
3. **Chart metric label.** `величины -меры` = F₁-меры (missing subscript was an
   embedded image; the preceding sentence names F1 explicitly). The chart plots F1.
4. **Hybrid scheme / 84-function construction / canonicalization scope / query
   counting / zero denominators.** All implementation choices where the manual is
   silent, incomplete, or descriptive rather than prescriptive — recorded above,
   never attributed to the manual.

## Shared architecture requirements

- Variant selection lives in `shell.svelte.ts` (keyed per lab, validated on lab
  switch, falling back to the first variant of the new lab).
- Registry-driven dispatch: `src/routes/+page.svelte` renders the active lab's
  view through a static folder→view map; a lab renders only when its view is
  registered (not merely because a store module exists).
- Lab 1 corpus exposed through a narrow read-only accessor for Lab 3 (id, name,
  text) — no UI internals imported.
- Pure algorithm modules (no Svelte imports) so tests run under Bun directly;
  browser File APIs and toasts stay in the stores.
- Technical comments/docs in English; student-facing UI text and errors in Russian.
